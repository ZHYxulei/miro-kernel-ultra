### 内核配置精简 / Slimmer kernel configuration

- 将一批没有必要内建（`=y`）的驱动与子系统改为按模块编译（`=m`），缩小内核镜像体积：
  - `CONFIG_PINCTRL_MSM`、`CONFIG_MQ_IOSCHED_ADIOS`
  - `CONFIG_IP_SET`、`CONFIG_IP_SET_HASH_IP`、`CONFIG_IP_SET_HASH_NET`、`CONFIG_NETFILTER_XT_SET`
  - `CONFIG_NETFILTER_XT_MATCH_ADDRTYPE`、`CONFIG_NETFILTER_XT_MATCH_RECENT`、`CONFIG_NETFILTER_XT_TARGET_LOG`
- 移除 `build.config.msm.miro` 中对 `CONFIG_PINCTRL_MSM/SUN/QCOM_SPMI_PMIC` 的强制 `=y` 覆盖（该覆盖是早期为绕过 `rsmc_driver.ko` 符号错误而加的历史 workaround，现已不再需要）。
- Several drivers and subsystems that had no reason to be built in (`=y`) are now
  built as modules (`=m`), shrinking the kernel image: `CONFIG_PINCTRL_MSM`,
  `CONFIG_MQ_IOSCHED_ADIOS`, the `ipset`/`xt_set`/`xt_LOG`/`xt_RECENT`/
  `xt_ADDRTYPE` netfilter chain, and others.
- Dropped the forced `=y` overrides for `CONFIG_PINCTRL_MSM/SUN/QCOM_SPMI_PMIC`
  in `build.config.msm.miro`. That override was a historical workaround for
  `rsmc_driver.ko` symbol errors and is no longer needed.

### 修复刷机包缺少模块的问题 / Fixed missing modules in the flashable ZIP

上一版的刷机包实际上不含任何内核模块：kbuild 会先 `chdir` 进输出目录，导致传给
`modules_install` 的相对路径 `INSTALL_MOD_PATH` 被二次重锚定到 `out/out/...`，
模块被装到了错误位置，打包时被静默跳过。现在输出目录统一绝对化，并在
`modules_install` 之后校验安装树确实产出了 `.ko`，缺失即构建失败。

Previous ZIPs shipped without any kernel module: kbuild `chdir()`s into the output
directory, so the relative `INSTALL_MOD_PATH` handed to `modules_install` was
re-anchored to `out/out/...`. The modules landed somewhere the packager never
looked and were dropped silently. The output directory is now always absolute and
the build fails loudly if `modules_install` produced no `.ko`.

### 模块剥离与调试符号归档 / Stripped modules plus a debug symbols archive

修复模块打包后，刷机包体积从 18 MB 涨到 105 MB：随包发布的模块带着完整调试信息。
现在 `modules_install` 会产出两棵模块树——一棵保留调试信息，一棵用
`INSTALL_MOD_STRIP=1` 剥离——刷机包只携带剥离后的模块（体积回落），未剥离的模块
连同 `vmlinux`、`System.map`、`.config` 一起打包成
`miro-kernel-ultra-debug-<版本>.tar.zst` 单独发布，用于把崩溃地址还原成函数名
（`addr2line` / `objdump`）。构建时若剥离未生效（release 树不小于 debug 树）或两棵树
模块数量不一致，会直接报错而不是悄悄发一个超大的包。

Once the missing-module bug was fixed the flashable ZIP grew from 18 MB to 105 MB
because the modules carried full debug info. `modules_install` now produces two
trees from the same objects — one keeping debug info, one stripped via
`INSTALL_MOD_STRIP=1`. The ZIPs ship the stripped tree, while the unstripped
modules plus `vmlinux`, `System.map` and `.config` are published separately as
`miro-kernel-ultra-debug-<version>.tar.zst` for turning crash addresses back into
function names (`addr2line` / `objdump`). The build now fails loudly if stripping
had no effect or if the two trees disagree on the module count, instead of
silently shipping an oversized package.

### CI：产物校验补强 / Stricter artifact verification

- 刷机包现在必须包含 `modules/**/*.ko`，否则校验直接失败（此前该校验是条件式的，模块缺失时会被跳过）。
- 校验刷机包内模块数量与构建产物一致，避免部分模块被漏打。
- `SHA256SUMS-*` 现在记录裸文件名，`sha256sum -c` 可在下载目录直接使用。
- The ZIP must now contain `modules/**/*.ko` or verification fails outright; the
  old check was conditional and skipped exactly when modules went missing.
- The module count inside the ZIP is compared against the build output.
- `SHA256SUMS-*` now store bare filenames so `sha256sum -c` works directly in the
  download directory.

### CI：真实启动冒烟测试 / Real boot smoke test

- 新增 `scripts/ci/smoke-boot-test.sh`：用 QEMU（`-M virt`）真实启动刚构建出的
  `Image`，通过极简 initramfs 进入用户态，断言内核完成 MMU/GIC/定时器/PL011
  串口/devtmpfs 初始化且 `/init` 执行成功，并检查启动日志中没有 panic 或 oops。
- CI 新增 `smoke-test` job，`release` 依赖它，未通过启动测试的构建不会发布。
- Added `scripts/ci/smoke-boot-test.sh`, which boots the freshly built `Image`
  under QEMU (`-M virt`) with a minimal initramfs and asserts that the kernel
  reaches userspace with no panic or oops in the console log.
- A new `smoke-test` CI job gates the `release` job: a build that cannot boot is
  never published.

### 夜间构建 / Nightly builds

- 新增每日定时构建（北京时间 02:00），产物标记为 `nightly-YYYYMMDD`，便于随时拿到最新的可刷入产物。
- A nightly scheduled build (02:00 Asia/Shanghai) publishes `nightly-YYYYMMDD`
  artifacts so a current flashable build is always available.

### 发布说明 / Release notes

- Release 说明改为中英双语，并由 `scripts/ci/release-notes.sh` 生成，包含变更内容、产物清单、刷入方法、校验方式与设备检测信息。
- Release notes are now bilingual and generated by `scripts/ci/release-notes.sh`,
  covering changes, release contents, installation, verification and the device
  check list.
